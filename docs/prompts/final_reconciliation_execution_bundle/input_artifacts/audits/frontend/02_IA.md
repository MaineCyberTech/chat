# UI/UX Phase 2 — User Journeys and Information Architecture

## 1. Major User Journeys

### Current Repo — 3 Core Journeys

**Journey A: First-time user → workspace**

1. User lands on `/` → LandingShell (Get Started CTA)
2. Clicks "Get Started" → `/login`
3. Enters email → magic link sent
4. Clicks magic link → authenticated, lands back on `/`
5. HomePage detects `user` + `noWorkspace` → shows "Create your first workspace" prompt
6. Clicks "Create Workspace" → dialog → submits → redirects to `/[slug]`

**Journey B: Returning user → channel → message**

1. Lands on `/` → HomePage detects user + existing workspaces → auto-redirects to `/[firstWorkspaceSlug]`
2. Sees workspace home page with "Select a channel" prompt
3. Clicks channel in sidebar → navigates to `/[slug]/[channelId]`
4. Sees ChatView with message list
5. Types message → Send → real-time broadcast

**Journey C: Channel management**

1. From sidebar → clicks "+ Add channel" → dialog opens
2. Enters name + optional topic → creates channel
3. Channel list refreshes → new channel visible

### Reference Repo — 5+ Core Journeys

**Journey A: Auth → Portal dashboard**

1. Lands on public marketing page
2. Navigates to `/login` → enters email → magic link
3. Redirects to `/portal/dashboard` with org context, stats, project list

**Journey B: Project management**

1. From dashboard → clicks project → `/portal/projects/[projectId]`
2. Sees task list, timeline, calendar views
3. Can create/edit tasks, assign, change status

**Journey C: Support/ticket flow**

1. From sidebar → "Support" → `/portal/support`
2. Lists tickets → clicks one → `/portal/support/[ticketId]`
3. Sees conversation thread, SLA status, priority

**Journey D: Document management**

1. From sidebar → "Documents" → `/portal/documents`
2. Lists documents → clicks one → viewer with versioning

**Journey E: Admin management**

1. From header → admin switch → `/admin/`
2. Manages users, organizations, roles, permissions, webhooks

## 2. Information Architecture Comparison

| Aspect               | Reference                                                                                          | Current                                     | Assessment                                       |
| -------------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------- | ------------------------------------------------ |
| **Depth**            | 3-4 levels (dashboard → projects → [projectId])                                                    | 2-3 levels (workspace → channel → messages) | Similar depth                                    |
| **Breadth**          | 8+ top nav items (dashboard, projects, tickets, documents, billing, notifications, profile, admin) | 2 top sections (workspaces, channels)       | Current is simpler                               |
| **Navigation**       | Header tabs + sub-nav + breadcrumbs                                                                | Sidebar user/workspace/channel tree         | Current is more chat-app-appropriate             |
| **Discoverability**  | Org switcher, global search, notification bell                                                     | Workspace list, channel list, search bar    | Reference has more discovery tools               |
| **Entry point**      | Dashboard (aggregated data)                                                                        | Workspace/page or channel page              | Different models — dashboard vs. workspace-first |
| **Cross-cutting**    | Global search across all entities                                                                  | Message search only                         | Reference has broader search                     |
| **Admin/user split** | Clear admin namespace `(admin)`                                                                    | No admin concept                            | Reference has role-aware IA                      |

## 3. Navigation Strengths

### Current Repo

- **Auto-redirect to workspace**: After auth, user is immediately taken to their content — no intermediate dashboard
- **Sidebar indentation**: Clear visual hierarchy (user → workspaces → channels)
- **Active state highlighting**: `bg-gray-100` on active workspace/channel — good affordance
- **Collapsible sections**: SidebarGroup component can collapse workspaces/channels (though currently unused in app-sidebar)
- **Minimal chrome**: Header only shows when logged in — clean

### Reference Repo

- **Org switcher**: Multi-org support with dropdown — critical for MSP use case
- **Global search**: Search across all portal entities, always accessible
- **Breadcrumbs**: Built into layout (PortalBreadcrumbs, AdminBreadcrumbs)
- **Notification bell**: Persistent, shows unread count — good for async workflows
- **Role-aware navigation**: Admin users get additional nav items — strong UX pattern

## 4. Navigation Friction Points

### Current Repo

| Issue                                | Location        | Impact                                                                                |
| ------------------------------------ | --------------- | ------------------------------------------------------------------------------------- |
| No breadcrumbs                       | All pages       | User can't see where they are in the hierarchy — especially with routing params       |
| No back navigation                   | Channel pages   | Only way to go back is browser back button or clicking sidebar                        |
| Workspace slug auto-redirect         | `/` page.tsx    | If user has multiple workspaces, always goes to first — no workspace selection screen |
| Channel ID shown as channel name     | ChatView header | `# {channelId}` shows the raw ID, not the channel name/display name                   |
| No workspace/channel counts          | Sidebar         | No indication of how many workspaces or channels exist                                |
| No "switch workspace" affordance     | Sidebar         | Workspace list is at bottom — user must scroll to see other workspaces                |
| Channel list doesn't collapse        | Sidebar         | All channels always visible — no collapsible groups                                   |
| No favicon or app icon               | layout.tsx      | Missing from metadata                                                                 |
| Loading states use "Loading..." text | Multiple        | Text loading states feel less polished than skeleton components                       |

### Reference Repo

| Issue                   | Location                   | Impact                                                                  |
| ----------------------- | -------------------------- | ----------------------------------------------------------------------- |
| 93KB component          | AdminDocumentsCenterClient | Extreme file size implies poor component decomposition — slow rendering |
| No shared UI library    | All pages                  | Visual inconsistency across admin/portal/public                         |
| Server component layout | (portal) layout            | Full page data fetching before render — slower perceived load           |

## 5. Workflow Efficiency Findings

### Current Repo

| Workflow           | Steps                                                     | Efficiency                    |
| ------------------ | --------------------------------------------------------- | ----------------------------- |
| Send first message | 3 steps: enter email → click magic link → type message    | Efficient — 2 clicks + typing |
| Create workspace   | 2 steps: click "Create Workspace" → enter name            | Efficient — 1 dialog          |
| Create channel     | 2 steps: click "+ Add channel" → enter name + topic       | Efficient — 1 dialog          |
| Edit message       | 3 steps: hover → click edit icon → modify → Save          | Good — inline editing         |
| Reply to message   | 2 steps: hover → click reply icon → type                  | Good — shows reply indicator  |
| File upload        | 3 steps: click attach → select file → image/text embedded | Good — inline attachment      |

### Reference Repo

| Workflow           | Steps                                                                 | Efficiency                   |
| ------------------ | --------------------------------------------------------------------- | ---------------------------- |
| Create ticket      | Multiple steps: navigate to support → new ticket → fill form → submit | Moderate — more fields       |
| Approve membership | Admin: navigate to org → members → approve                            | Moderate — nested navigation |
| Document upload    | Multiple steps: navigate to documents → upload → set permissions      | Moderate                     |

## 6. Similarity Opportunities

| What                         | Current State         | Suggested Change                          | Benefit                               |
| ---------------------------- | --------------------- | ----------------------------------------- | ------------------------------------- |
| Breadcrumbs                  | None                  | Add breadcrumb to workspace layouts       | Better orientation in deep routes     |
| Channel display name         | Shows `channelId`     | Fetch channel name and display it         | Clearer UI                            |
| Global search scope          | Messages only         | Optionally search channels + workspaces   | Better discoverability                |
| Navigation with active state | Workspace list only   | Add collapsible channel groups            | Better organization for many channels |
| Loading polish               | Mixed skeleton + text | Use Skeleton consistently                 | Visually consistent                   |
| Favicon/app icon             | None                  | Add to layout.tsx                         | Professional polish                   |
| Channel counts               | None                  | Show "(N)" badge next to Channels heading | Quick orientation                     |

## 7. Areas That Should Not Be Reorganized Without Strong Justification

| Area                                                       | Reason                                                                                            |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `(workspace)/[workspaceSlug]/[channelId]/` route structure | Clean 3-segment URL pattern — workspace → channel → message. Changing would break existing links. |
| Sidebar as primary navigation                              | Works well for chat apps — users expect this model (Slack, Discord).                              |
| Auto-redirect to first workspace                           | Efficient for single-workspace users. If multi-workspace becomes common, add workspace picker.    |
| Client-side auth context                                   | Works well. No need to migrate to server-side auth for current scale.                             |
| Inline message editing                                     | Direct manipulation pattern — users expect this. No need for modal.                               |
